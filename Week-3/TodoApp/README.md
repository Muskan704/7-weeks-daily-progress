
# 📘 FastAPI + SQLAlchemy Database Setup (Detailed Guide)

This project demonstrates a **fully explained database configuration** for a FastAPI application using **SQLAlchemy ORM** with **SQLite** as the database backend.

The setup follows **FastAPI‑recommended best practices** and is designed to be:

*   Beginner friendly
*   Easy to extend
*   Safe for concurrent requests
*   Ready for migration to PostgreSQL/MySQL in production

***

## 📌 Why This File Exists

In any FastAPI project, database configuration is **the foundation**.  
This file is responsible for:

*   Establishing database connectivity
*   Managing transactions safely
*   Enabling ORM model definitions
*   Ensuring thread‑safe behavior with FastAPI

If this file is incorrect, **everything else breaks**.

## 📄 The Database Configuration Code

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.ext.declarative import declarative_base

SQLALCHEMY_DATABASE_URL = "sqlite:///./todos.db"

engine = create_engine(
    SQLALCHEMY_DATABASE_URL,
    connect_args={"check_same_thread": False}
)

SessionLocal = sessionmaker(
    autocommit=False,
    autoflush=False,
    bind=engine
)

Base = declarative_base()
```

***

## 🔍 Deep Explanation (Line by Line)

***

## 1️⃣ Import Statements

```python
from sqlalchemy import create_engine
```

### What this does:

*   Imports SQLAlchemy’s **engine creation utility**
*   The engine is responsible for:
    *   Connecting to the database
    *   Executing SQL
    *   Managing connection pooling

✅ The engine is **NOT** a session  
✅ The engine is **NOT** tied to a request

Think of the engine as a **database gateway**, not a worker.

***

```python
from sqlalchemy.orm import sessionmaker
```

### What this does:

*   Imports a **session factory**
*   Used to generate new Session objects
*   Each Session represents:
    *   One database transaction
    *   One unit of work

✅ FastAPI uses one session per request

***

```python
from sqlalchemy.ext.declarative import declarative_base
```

### What this does:

*   Enables the **ORM declarative system**
*   Allows you to define database tables using Python classes
*   Required for model creation

Without this import:
❌ ORM models cannot exist  
❌ Tables cannot be autogenerated

***

## 2️⃣ Database URL Configuration

```python
SQLALCHEMY_DATABASE_URL = "sqlite:///./todos.db"
```

### How to read this URL:

| Component    | Meaning                |
| ------------ | ---------------------- |
| `sqlite`     | Database type          |
| `:///`       | Path separator         |
| `./todos.db` | Database file location |

✅ Uses SQLite  
✅ Stores data in a local `.db` file  
✅ Automatically creates DB if it doesn’t exist

***

## 3️⃣ Creating the Database Engine

```python
engine = create_engine(
    SQLALCHEMY_DATABASE_URL,
    connect_args={"check_same_thread": False}
)
```

### What the engine actually does

*   Holds connection configuration
*   Connects **on demand**, not immediately
*   Translates ORM operations into raw SQL
*   Manages thread‑safe connection reuse

***

### Why `check_same_thread=False`?

SQLite **restricts connections to a single thread by default**.

FastAPI:

*   Uses asynchronous execution
*   Handles concurrent requests
*   Operates across multiple threads

Without this:

    sqlite3.ProgrammingError:
    SQLite objects created in a thread can only be used in that same thread

✅ This setting allows SQLite to work with FastAPI  
⚠️ This is **SQLite‑only**  
⚠️ Not required for PostgreSQL or MySQL

***

## 4️⃣ Session Factory (`SessionLocal`)

```python
SessionLocal = sessionmaker(
    autocommit=False,
    autoflush=False,
    bind=engine
)
```

### What `SessionLocal` really is

*   ❌ NOT a database session
*   ✅ A **factory** that creates database sessions

Usage:

```python
db = SessionLocal()
```

Each call gives a **fresh session**, isolated per request.

***

### `bind=engine`

Links every session to the correct database engine.

✅ Sessions know *where* to send queries  
✅ Decouples session logic from DB details

***

### `autocommit=False`

Means:

*   SQL changes are NOT saved automatically
*   You must call:

```python
db.commit()
```

Benefits:

*   Prevents accidental writes
*   Enables rollback
*   Ensures transaction safety

***

### `autoflush=False`

Controls when SQL statements are sent to the database.

With autoflush OFF:

*   SQL executes only when explicitly requested
*   Predictable behavior
*   Avoids hidden queries

✅ Recommended for clean API logic

***

## 5️⃣ Declarative Base (`Base`)

```python
Base = declarative_base()
```

### What this creates

*   A **base ORM class**
*   Stores all metadata for:
    *   Tables
    *   Columns
    *   Constraints
    *   Relationships

All models MUST inherit from this.

Example:

```python
class Todo(Base):
    __tablename__ = "todos"
    id = Column(Integer, primary_key=True)
```

***

### Why this is critical

Later, table creation happens using:

```python
Base.metadata.create_all(bind=engine)
```

✅ SQLAlchemy knows:

*   Which tables exist
*   How to create them
*   How to map rows to Python objects

***

## 🔁 How FastAPI Uses This Setup

### Typical Dependency Pattern

```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### What happens per request:

1.  Session is created
2.  Endpoint executes queries
3.  Transaction commits (or fails)
4.  Session closes safely

✅ No connection leaks  
✅ Thread safe  
✅ Clean lifecycle
